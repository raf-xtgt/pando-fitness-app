# Pando

A no-pressure walking and running app. Your real steps move a runner, with a mascot companion, along an endless isometric park, and a wooden sign marks where each walk ended. Five minutes after you stop, a warm report arrives as a push notification.

Built with **Flutter** (Android) + **Flame** for the park, and **Serverpod 4** for the backend (models, migrations, anonymous auth, future calls), running on **Google Cloud Run** with **Neon** Postgres.

## Layout

| Folder | What |
|---|---|
| `pando_flutter/` | The Android app |
| `pando_server/` | The Serverpod server |
| `pando_client/` | Client code generated by Serverpod (don't edit) |

## Run it locally

Needs Flutter, the Serverpod CLI (`serverpod`), and an Android phone on the same Wi-Fi as your computer.

```bash
cd pando_server && serverpod start --no-flutter          # local Postgres, migrations, port 8080
cd pando_flutter && flutter run --dart-define=SERVER_URL=http://<your-laptop-ip>:8080/
```

Optional build flags: `--dart-define=DEMO=true` (long-press "Your walks" to seed three past walks) and `--dart-define=TEST_GOAL_STEPS=30` (a tiny goal for indoor testing).

Push notifications need your own Firebase project (`flutterfire configure`) and a service account key at `pando_server/config/service-account.json` (gitignored). Without the key, the server only logs pushes, and the report opens from the Home row after 5 minutes.

## Cloud

One Docker image runs in two roles:
- **Cloud Run service** (`--role serverless`): answers the app.
- **Cloud Run job** (`--role maintenance`): started by a Cloud Tasks alarm 5 minutes after each walk. It runs the due Serverpod future call (the push) and exits.

Secrets come from Secret Manager as `SERVERPOD_*` env vars and are never in the repo or the image.
